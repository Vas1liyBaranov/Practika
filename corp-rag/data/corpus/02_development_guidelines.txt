РЕГЛАМЕНТ РАЗРАБОТКИ

1. Разработка ведётся в Git с использованием feature-веток.
2. Каждый Pull Request должен проходить код-ревью минимум одним разработчиком.
3. Ветка main должна быть всегда в рабочем состоянии (зелёные тесты).
4. Требования к коду: PEP8, аннотации типов, документация.
5. Перед слиянием обязательны успешные автотесты (unit + интеграционные).
6. Названия веток: feature/название-задачи, hotfix/название-исправления.
7. Коммиты должны быть осмысленными: feat:, fix:, docs:, chore:, refactor:.
8. Код-ревью проводится минимум одним разработчиком, критичные изменения — двумя.
9. После ревью автор вносит правки и запрашивает повторную проверку.
10. Ветка удаляется после успешного слияния в main.
11. Для крупных задач создаётся дизайн-документ перед началом разработки.
12. Используется CI/CD: GitHub Actions для автоматических проверок.
13. Деплой на staging происходит автоматически после мержа.
14. Релизы на production — по расписанию (вторник, четверг).

# КАК СОЗДАТЬ НОВУЮ ВЕТКУ В GIT:

1. Убедись, что ты на актуальной ветке main:
   git checkout main
   git pull origin main

2. Создай новую ветку:
   git checkout -b feature/название-задачи

3. Работай в ветке, делай коммиты:
   git add .
   git commit -m "feat: описание изменений"

4. Отправь ветку на GitHub:
   git push -u origin feature/название-задачи

5. Создай Pull Request на GitHub с описанием изменений.
6. Дождись ревью и внеси правки.
7. После одобрения выполни squash и слей ветку.
8. Удали ветку после слияния.
